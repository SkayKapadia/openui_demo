# India Open Data Dashboard

Ask questions about India's development data and get **generated dashboards**, including **live dashboards that are saved in your own Postgres and load fresh data every time they open**. Built with the open-source [OpenUI](https://openui.com) packages. No hosted dashboard service is involved.

> Data: [World Bank World Development Indicators](https://data.worldbank.org/), CC BY 4.0. No API key needed.

## Self-hosted live dashboards

This is a self-hosted take on a dashboard API, in answer to [thesysdev/openui#1635](https://github.com/thesysdev/openui/issues/1635): the dashboard is generated once, stored in Postgres, and from then on loads its own data from Postgres with **no LLM call**.

```
 1. Generate (once)                          2. Open or filter (every time, no LLM)

 chat ─► create_dashboard tool               browser: OpenUI <Renderer toolProvider>
           │  LLM writes OpenUI Lang                    │  Query("get_series", {country: $country})
           │  with Query() + $filters                   ▼
           ▼                                  POST /api/tools  ─►  read-only SQL  ─►  Postgres
   OpenUI parser validates it                                      (dashboard_reader role)
           │  (one retry with the errors)
           ▼
   dashboards table in Postgres  ─────────►  /d/<id> loads the saved program
   (dashboard_store role)
```

- **The model never sees or writes the data.** It writes a program such as `gdp = Query("get_series", {indicator: "NY.GDP.PCAP.CD", country: $country})` and binds components to `gdp.labels` and `gdp.values`.
- **Filters are `$variables`.** A `Select` bound to `$country` re-runs only the queries that use it.
- **Every page shows its own query log** ("9 queries · 0 LLM calls") and the saved source.
- **Three database roles:** the loader's owner role, `dashboard_reader` (SELECT only, read-only transactions, 5 s timeout) for data tools, and `dashboard_store`, which can touch only the `dashboards` table.

Try it without an LLM: `npm run db:seed`, then open `/d/country-profile` (a hand-written sample in `db/seed/`).

## Quick start

Requirements: Node 22+, Docker, and an [OpenRouter](https://openrouter.ai/keys) key.

```bash
npm install
cp .env.example .env        # then set passwords and OPENROUTER_API_KEY
npm run db:up               # Postgres on localhost:54329, schema and roles created
npm run load:worldbank      # ~8,000 rows, about 2 minutes
npm run db:seed             # the hand-written sample dashboard
npm run dev                 # http://localhost:3000
```

In the chat, ask for example: *"Make a live dashboard of India's infrastructure with a start year filter."* Saved dashboards are listed at `/dashboards`.

The default model is `anthropic/claude-haiku-5.5` (about $0.002 per chat answer; a live dashboard costs a little more because it is generated by a second call). Free OpenRouter models work but make more mistakes in OpenUI Lang.

## Where things are

| Piece | File | Notes |
|---|---|---|
| Schema | `db/schema.sql` | `countries`, `indicators`, `observations`, `dashboards` |
| Docker init | `db/init/01_init.sh` | Schema and the two app roles, on first start |
| Loader | `scripts/load-worldbank.mts` | Idempotent upserts. Edit `scripts/worldbank-catalog.mts` to add countries or indicators |
| Dashboard data tools | `src/lib/data-tools.ts` | `get_series`, `get_comparison`, `get_snapshot`: fixed SQL, lenient arguments, flat results that bind directly |
| Browser data endpoint | `src/app/api/tools/route.ts` | `{ name, args }` → `{ result }`. Named tools only, no SQL in the request |
| Generation | `src/lib/dashboard-generator.ts` | OpenUI's prompt with `tools`, `toolCalls` and `bindings`; validated with `createParser`; one repair attempt |
| Storage | `src/lib/dashboard-store.ts` | Saved OpenUI Lang programs in Postgres |
| Live page | `src/app/d/[id]/page.tsx`, `src/components/LiveDashboard.tsx` | `Renderer` from `@openuidev/react-lang` with a `toolProvider` function map |
| Chat | `src/app/api/chat/route.ts`, `src/lib/tools.ts`, `src/lib/system-prompt.ts` | Vercel AI SDK → OpenRouter. Quick answers use chat tools; `create_dashboard` makes a live dashboard |

## Using a hosted Postgres (e.g. Neon for a Vercel deploy)

The code only reads connection strings, so any Postgres works:

```bash
DATABASE_URL_ADMIN=<hosted-url> STORE_PASSWORD=<password> npm run db:schema
DATABASE_URL_ADMIN=<hosted-url> npm run load:worldbank
```

Then set `DATABASE_URL` (a read-only user), `DATABASE_URL_STORE` (the `dashboard_store` user) and `OPENROUTER_API_KEY` in your host's environment settings.

## Scripts

| Command | What it does |
|---|---|
| `npm run db:up` / `db:down` | Start / stop the Postgres container |
| `npm run db:schema` | Apply `db/schema.sql` and create the `dashboard_store` role |
| `npm run db:seed` | Save the sample dashboards in `db/seed/` |
| `npm run load:worldbank` | Fetch World Bank data and upsert it into Postgres |
| `npm run validate -- <file>` | Check an OpenUI Lang file against the component library |
| `npm run dev` | Generate the OpenUI spec and start Next.js |

## Known limits

- **Missing values inside a line chart are drawn as 0** by OpenUI's charts ([#1611](https://github.com/thesysdev/openui/issues/1611)). The data tools avoid trailing gaps, but an indicator with gaps in the middle (adult literacy) still shows dips.
- **Chart series colours are close together**, so several countries on one chart are hard to tell apart ([#1602](https://github.com/thesysdev/openui/issues/1602)).
- There is no sign-in: every saved dashboard is visible to anyone who can open the app.
